🤔 ¿Por qué dominar la terminal en ML?

Los servidores de entrenamiento no tienen interfaz gráfica. SSH, tmux, y scripts bash son tus únicos aliados cuando entrenas en la nube o en clusters de GPU.

🖥️

Servidores remotos

AWS EC2, GCP VMs, HPC clusters — todos son Linux sin GUI. La terminal es la única interfaz.

🤖

Automatización

Un script corre 100 experimentos mientras duermes. Clic a clic es imposible a esa escala.

📊

Procesamiento de datos

grep | awk | sort procesan GBs en segundos sin cargar nada en memoria Python.

🔍

Debug de producción

tail -f, grep en logs, top — diagnóstico en tiempo real sin reiniciar nada.

🚀

CI/CD pipelines

GitHub Actions, Docker, Kubernetes — todos ejecutan scripts bash. Entenderlos es clave.

⚡

Velocidad

Un experto en terminal es 5–10× más rápido que uno que depende de GUI para operaciones de archivos.

💡 La realidad: Cuando preguntas en Stack Overflow por cómo hacer X en Python, la respuesta CLI de una línea muchas veces es 100× más rápida. wc -l archivo.csv vs un script Python que carga el CSV entero.

📝 Manejo de Archivos y Texto

En ML manejas datasets, logs, configuraciones y modelos constantemente. Estos comandos te permiten inspeccionarlos y transformarlos sin abrir Python. 

# ── Inspección rápida ─────────────────────────────────
cat archivo.csv           # Print completo (cuidado con archivos grandes)
head -5 datos.csv         # Primeras 5 líneas (muy útil para CSVs)
tail -20 training.log     # Últimas 20 líneas del log
less datos.csv            # Lector paginado (tecla q para salir)

# ── Contar ────────────────────────────────────────────
wc -l datos.csv           # Número de líneas (= filas del dataset)
wc -w archivo.txt         # Palabras
wc -c archivo.bin         # Bytes

# ── Buscar ────────────────────────────────────────────
grep "val_loss" training.log             # Buscar patrón
grep -c "ERROR" training.log             # Contar coincidencias
grep -v "DEBUG" training.log             # Invertir búsqueda (excluir)
grep -E "epoch [0-9]+" training.log      # Regex extendida

# ── Comparar ──────────────────────────────────────────
diff modelo_v1.py modelo_v2.py           # Diferencias entre archivos
diff -u modelo_v1.py modelo_v2.py        # Formato unificado (como git diff)

# ── Comprimir y descomprimir ──────────────────────────
tar -czf backup.tar.gz modelos/          # Comprimir directorio
tar -xzf backup.tar.gz                   # Descomprimir
gzip datos.csv                           # Comprimir un archivo
gunzip datos.csv.gz                      # Descomprimir
zip -r proyecto.zip src/ data/processed/ # Crear zip

# ── Copiar, mover, eliminar pasivos ───────────────────
cp -r data/processed/ backups/           # Copiar directorio recursivo
mv experimento_v1/ experimento_final/    # Mover / renombrar
rm -rf logs/old/                         # ⚠️ Borrar recursivo — sin papelera
⚠️ rm -rf no tiene papelera de reciclaje. Ante la duda usa mv a una carpeta trash/ temporal. En producción, siempre prefiere -i (interactivo) para confirmar.

⚙️ Procesos y Variables de Entorno

Al entrenar modelos necesitas manejar procesos en background, revisar uso de GPU/CPU, y configurar el entorno con variables que Python leerá en tiempo de ejecución. 

# ── Gestión de procesos ───────────────────────────────
ps aux | grep python              # Ver procesos Python corriendo
kill 12345                        # Terminar proceso por PID
kill -9 12345                     # Forzar terminación (SIGKILL)
pkill -f "train.py"               # Matar por nombre del script

# Background y foreground
python train.py &                 # Correr en background
jobs                              # Ver procesos background de esta shell
fg %1                             # Traer proceso 1 al foreground
Ctrl+Z                            # Suspender proceso actual
bg %1                             # Continuar proceso 1 en background

# ── Variables de entorno ───────────────────────────────
export MI_VAR="valor"             # Definir variable de entorno
echo $MI_VAR                      # Usar variable
printenv                          # Ver todas las variables
env | grep PYTHON                 # Filtrar variables

# Variables críticas para ML
export PYTHONPATH="$PWD/src:$PYTHONPATH"
export CUDA_VISIBLE_DEVICES="0,1"       # Usar GPU 0 y 1
export TF_CPP_MIN_LOG_LEVEL="3"         # Silenciar logs TensorFlow
export TOKENIZERS_PARALLELISM="false"   # HuggingFace warning

# ── .env files — secrets y config del proyecto ────────
cat > .env << 'EOF'
WANDB_API_KEY=tu_api_key_aqui
DATABASE_URL=postgresql://user:pass@localhost/ml_db
MODEL_CACHE=/data/models
EOF

# Cargar en bash
set -a; source .env; set +a

# En Python con python-dotenv
# from dotenv import load_dotenv
# load_dotenv()
ps aux | grep python 
usuario  12345  98.2  2.1  python train.py --epochs 100
usuario  12346  0.0   0.1  grep --color=auto python
⚠️ Nunca hagas export API_KEY=... en un script que commitees a Git. Usa un .env listado en .gitignore y compártelo de forma segura (1Password, AWS Secrets Manager, etc.).
